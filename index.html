Project notebook — computer vision prototype

A camera watches a bouldering wall, finds the holds, tracks the climber, and suggests the next move.

Three models I trained and wrote myself, stepped through here with real output on real photos from actual climbing sessions.

Why a walkthrough, not a live app? The full system runs on AWS Lambda, S3, and a phone camera — infrastructure I'm not paying to keep warm for a portfolio page nobody's actively climbing in front of. Every image below is real model output, generated once and captured here rather than served live.

One honest gap: I no longer have the original HRNet ONNX weights, so the two pose skeletons shown were reconstructed by hand from HRNet renders I'd saved, then checked point-by-point against them. Detection, color clustering, hold matching, and scoring are all the unmodified original code running on real data.

How the pipeline works

01

Hold detection

A YOLOv8 model, trained on ~300 hand-labeled photos, finds every bolt-on hold (single class: handle). Each detected hold is cropped, K-means finds its dominant color, and a second K-means pass clusters holds into "tracks" — the color-coded routes climbers actually follow.

02

Pose tracking

HRNet estimates a 17-point COCO skeleton for the climber every frame — shoulders, wrists, hips, ankles and more. The camera stays fixed on a tripod, so the wall only needs scanning once; pose tracking runs continuously as the climber moves.

03

Hold matching

For each hand and foot, the nearest detected hold becomes that limb's current position. From there, every same-track hold within roughly one body-length becomes a candidate next move — hands search upward, feet search below the hips.

04

Move scoring

A linear regression model, trained on relative limb-movement features, scores every candidate. It was still in early data collection when I paused the project, so treat scores as directional — a rough sort, not a precise ranking.
